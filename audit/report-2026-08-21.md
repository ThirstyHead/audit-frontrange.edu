## Findings & remediation

### F1 — `video-caption` (SC 1.2.2, critical) — Homepage
The homepage has a `<video>` element with no captions track.

**Fix**: add a `<track>` with a WebVTT file, or swap in a player that exposes native captions:

```html
<video controls preload="metadata" poster="...">
  <source src="tour.webm" type="video/webm">
  <track kind="captions" src="tour-captions.vtt" srclang="en" label="English" default>
</video>
```

If the video is purely decorative (muted, `aria-hidden="true"`, no speech), document that rationale and it does not need captions — otherwise it is a hard fail of 1.2.2.

### F2 — `duplicate-id-aria` (SC 4.1.1, critical) — All 4 pages
One element per page in the header search drawer (`#ou-search-div … .search__input`) fails ID uniqueness: an ARIA `id` referenced by `aria-*` (e.g. `aria-labelledby`/`aria-describedby`) is duplicated in the DOM, so the computed accessible name resolves ambiguously.

**Fix**: make the ID unique per instance (template counter/suffix) or drop the `aria-*` reference in favor of a visible `<label for="...">` that is itself unique. The pattern repeats verbatim across all four pages, so this is a shared header template — fix once in the header partial.

### F3 — `color-contrast` (SC 1.4.3, serious) — Header nav, up to 249 nodes
axe could not conclusively compute the foreground/background pair (incomplete), but the affected set is the same element: first-level header/mega-menu links (`.cluster li:nth-child(1) strong a`, `.c-header__menu1 ul li:nth-child(1) strong a`). On the program-finder page the rule flagged **249 nodes**, indicating the entire program list shares the low-contrast style.

**Fix**: sample computed colors on the live site, then raise the text color (or darken the background) until the ratio is ≥ **4.5:1** (≥ 3:1 only if the text is large: 24px / 18.66px bold+). Because the same selector pattern recurs on every page, this is again a shared stylesheet fix. Note: `strong a` inside nav lists — verify the *link* state (hover/focus) also retains ratio; axe often cannot read colors through transparent backgrounds, which is why the check is "incomplete" rather than a confirmed fail.
